# M0 spike: OCCT viewer in PySide6, with picking

Goal from [PLAN.md](PLAN.md): a box shows, orbits, and a face pick prints its
ID on Windows, Linux and macOS. Then decide OCP vs pythonocc-core.

## What is in the spike

| Piece | File | What it does |
|-------|------|--------------|
| Model | `modeler/core/model.py` | Bodies, global IDs for every face/edge/vertex, the selection. No Qt. |
| Commands | `modeler/commands/` | Registry, a minimal parser, the processor and log, and the M0 commands |
| Viewport | `modeler/viewport/occ_view.py` | OCCT AIS/V3d view embedded in a `QWidget`; orbit, pan, zoom; picking |
| Window | `modeler/gui/main_window.py` | Toolbar, command line (Up/Down history), output panel |
| Entry | `modeler/__main__.py` | `python -m modeler [script.cmd]`, `run`, `check` |

The rule from the plan holds already: **the viewport never changes the
model**. A click becomes the text `PICK, FACE, 12`, which goes through the
same processor as typed commands and lands in the log. Toolbar buttons do the
same (hover a button to see the command it runs). Because of that, a typed or
scripted `PICK` highlights exactly like a click.

### M0 commands

```text
BLOCK, x,y,z, dx,dy,dz        box from a corner
CYL, x,y,z, r, h              cylinder along +Z
SPHERE, x,y,z, r
PICK, kind, id [, S|A|U]      what a click emits (A = add, U = remove)
SEL, S|A|U, kind, id1 [, id2] select an ID range
SEL, ALL, kind  /  SEL, NONE
PICKMODE, BODY|FACE|EDGE|VERTEX
VIEW, ISO|TOP|BOTTOM|FRONT|BACK|LEFT|RIGHT
FIT
CLEAR
LIST                          bodies and selection (not logged)
HELP [, command]              (not logged)
```

`!` starts a comment. Names are case-insensitive. Entity IDs are global per
kind: the first block has faces 1 to 6, the next body continues at 7. IDs are
never reused in a session (until `CLEAR`). Parameters, expressions, undo and
the full selection language come in M1/M2.

## Run it on your machine

Python 3.10 to 3.13. From the repository root:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows (PowerShell):
.venv\Scripts\Activate.ps1

pip install -e ".[test]"
python -m modeler check                  # versions + a kernel smoke test
python -m modeler scripts/m0_demo.cmd    # open the window and run the demo
```

`python -m modeler` alone opens an empty window. `python -m modeler run
scripts/m0_demo.cmd` runs a script without a window and prints the log.

Tests: `pytest` (on Linux without a desktop, use
`xvfb-run -a pytest` for the viewport tests).

**Linux notes.** On Wayland the app switches Qt to XWayland (`xcb`)
automatically, because OCCT needs an X11 window. If Qt says it could not load
the `xcb` platform plugin, install `libxcb-cursor0` (Ubuntu/Debian) or
`xcb-util-cursor` (Fedora/Arch).

## What to check on each OS

Please try these and tell me what happens (a screenshot helps if anything
looks wrong):

1. The window opens and shows a block, a cylinder and a sphere on a grey
   gradient, with the XYZ axes in the lower left. The top of the block and
   the top of the cylinder are orange (selected by the script).
2. **Orbit**: left-drag rotates. **Pan**: middle- or right-drag (or
   Shift+left-drag). **Zoom**: wheel zooms toward the cursor.
3. **Face pick**: click a face. It turns orange and the output shows
   `> PICK, FACE, n` and `selection: FACE n`. Ctrl+click adds, Alt+click
   removes, clicking empty space emits `SEL, NONE`.
4. **Edge / vertex / body pick**: press *Edge*, *Vertex* or *Body* in the
   toolbar (it runs `PICKMODE, ...`) and click again. Hovering highlights in
   light blue.
5. Type `PICK, FACE, 2` in the command line and press Enter: face 2 is
   highlighted without clicking.
6. Resize the window and drag it between monitors (HiDPI): the picture fills
   the view and clicks still hit what is under the cursor.
7. *Save log…* writes the session as a `.cmd` file. *Clear*, then *Run
   script…* on that file rebuilds the same model and selection.

## Decision: OCP vs pythonocc-core

On Linux (Xvfb + Mesa, OCP 8.0.1, PySide6 6.12, Python 3.13) everything above
works and is covered by `tests/test_viewport.py`: the view initializes from
the widget's native handle, and face, edge, vertex and body clicks map to the
right global IDs. CI runs the same tests on Linux and tries them on Windows
and macOS, but hosted runners have no GPU, so those runs only show whether
the native window handle wraps correctly.

Recommendation: **stay on OCP** if the checks above pass on your Windows or
macOS machine. Fall back to pythonocc-core only if the view stays black or
crashes there and the handle fix below does not solve it.

Where to look if a platform fails: `_native_window()` in
`modeler/viewport/occ_view.py`. It wraps `winId()` with `WNT_Window`
(Windows), `Cocoa_Window` (macOS) or `Xw_Window` (Linux), trying a plain
integer handle first and a capsule second.

## Notes for M1

- OCP 8 renamed some bindings (`TopTools_IndexedMapOfShape` became a
  `collections` type, `TopoDS.Vertex_s` became `TopoDS.Vertex`). The model
  handles both; new code should use small helpers rather than raw names.
- The model notifies listeners synchronously. A viewport display error is
  printed but never undoes a model change.
