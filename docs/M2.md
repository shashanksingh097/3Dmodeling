# M2, part 1: shapes on curves

M2 starts with the shapes-on-curves features from the plan (section 5.2),
so the twisted blade from M1 becomes one smooth sweep instead of 24 stacked
slices. The language reference is [LANGUAGE.md](LANGUAGE.md), section 9.

## What is in it

| Piece | File | What it does |
|-------|------|--------------|
| Curves and profiles | `modeler/geometry/curves.py` | Line, arc, polyline, spline, helix (taper, pitch law), equation curves; circle, ellipse, rect, polygon, star, slot, NACA airfoil on any plane |
| Loft and sweep engine | `modeler/geometry/sweep.py` | Path sampling, moving frames (minimal twist, Frenet, fixed), exact sweeps, scale-law sweeps, section sweeps with any laws, morphing |
| Commands | `modeler/commands/curve_handlers.py` | `LINE ARC POLYLINE SPLINE HELIX CURVE`, `CIRCLE ELLIPSE RECT POLYGON STAR SLOT AIRFOIL`, `LOFT SWEEP MORPH PIPE` |
| Display | `modeler/viewport/occ_view.py`, `handlers.py` | Curves drawn in orange; `HIDE` / `SHOW` (undoable, part of the history) |
| Examples | `scripts/blade_smooth.cmd`, `scripts/sweep_gallery.cmd` | The smooth blade; one example of each feature |
| Tests | `tests/test_curves.py` | Lengths and volumes checked against formulas, laws, morph, closed paths, history edits, both scripts |

## How a sweep is built

* **No laws:** OCCT's exact pipe (`BRepOffsetAPI_MakePipeShell`).
* **Only a scale law:** the same exact pipe with an evolution law. This is
  the robust choice on long winding paths such as springs.
* **Twist, stretch, offset, or several profiles:** the profile is placed at
  stations along the path, each one turned, scaled and moved by the laws in
  the moving frame there, and one smooth B-spline surface is fitted through
  all of them (`BRepOffsetAPI_ThruSections`). The number of stations is
  chosen from the twist, the bends of the path and the size change, and the
  result message reports it.
* **Morph:** every profile is resampled into the same number of points,
  starting from the same side and running the same way round, so the
  in-between sections blend without the surface twisting by accident.

The frame at the start of the path has its "up" axis at world +Z made
square to the path (world +Y if the path starts along Z). That is the same
rule profiles use for their plane, so a profile drawn with its normal along
the path lines up with the frame: profile X = side, profile Y = up.

## Things found on the way

* A NACA airfoil drawn as one closed spline with a cusp at the trailing edge
  looks right but breaks OCCT's volume integration (`VOL` came out 13% low).
  It is now two splines, upper and lower, tangent at the nose and sharp at
  the trailing edge; volumes match the formulas.
* `gp_Trsf.SetValues` expects a pure rotation; a scaled matrix gives wrong
  sections. Scaling is split off and applied separately.
* A sweep round a closed path makes a valid shell, but OCCT's `MakeSolid`
  gives an invalid solid at the seam. The result is rebuilt from the shell
  and fixed with `ShapeFix`.
* A section sweep through many stations on a long helix is too much for one
  fitted surface; that case uses the exact scale-law pipe instead. A twist
  law on a long helix still needs a lower `n` or a shorter path for now.
* Watch for name clashes: parameters and body names share one namespace,
  so a body called `span` is hidden by a parameter `SPAN`.
