# 3Dmodeling: Product and Technical Plan

This plan turns the idea in the README (every GUI action is a text command,
in our own command language) into a modeler that is usable for real work: precise solids,
freeform NURBS, equation-driven shapes, reusable parts, booleans, freehand
cuts and sculpting, with an AI assistant at the end.

It is organized as:

1. What the best tools do, and what we take from each
2. Key decisions (kernel, viewport, stack)
3. Data model: shapes, objects, IDs, history
4. The command language
5. Feature catalogue
6. Architecture and code layout
7. Milestones with exit criteria
8. Risks and how we handle them

---

## 1. What the best tools do

| Tool | What it does best | What we take |
|------|-------------------|--------------|
| **Command-driven FEA preprocessors** | Everything is a command; selection sets; parameters and loops; the log file is a complete script | The whole command philosophy, selection-set logic, parameters and loops |
| **SolidWorks / Fusion 360 / Onshape** | Sketch, constrain, extrude/revolve/sweep/loft; fillet, chamfer, shell, draft; feature tree you can edit and re-run; parts and assemblies | Sketch + feature workflow, editable history, components/instances |
| **Rhino (+ Grasshopper)** | NURBS curves and surfaces, loft, network surfaces, blend, rebuild, control-point editing, curvature analysis; visual/parametric scripting | NURBS toolbox, analysis (zebra, curvature), "script drives geometry" |
| **FreeCAD** | Open source on OCCT; Python console mirrors GUI actions | Proof that OCCT + Python + Qt works; the "GUI echoes Python" pattern |
| **OpenSCAD / CadQuery / build123d** | Models written as code; parameters at the top; CSG | Code-first modeling, parameter tables, reproducibility |
| **Blender** | Mesh editing (extrude, bevel, loop cut, knife), modifiers stack, sculpt mode, Python API for everything | Knife tool, non-destructive modifier idea, sculpt brushes |
| **ZBrush / Nomad** | Dynamic-topology sculpting, brushes, masking, remeshing | Sculpt mode on meshes (later phase) |
| **nTop / Fusion volumetric** | Implicit (field/SDF) modeling: lattices, smooth blends, equation-defined shapes | Equation-based implicit shapes with smooth booleans |

The gap we fill: none of the free tools combine **precise B-rep CAD, NURBS,
equation geometry and sculpting** under **one replayable command language**
with an AI on top.

## 2. Key decisions

### 2.1 Geometry kernel: Open CASCADE (OCCT)

OCCT is the only mature, free, Python-accessible B-rep kernel. It gives us
exact solids, NURBS curves and surfaces, booleans, fillets, chamfers, shells,
offsets, sweeps, lofts, STEP/IGES import and export, tessellation, and a
history API (which sub-shapes were modified or generated by an operation) that
we need for stable IDs.

- **Binding: OCP** (`cadquery-ocp`, installs with `pip`). It is the binding
  used by CadQuery and build123d and is kept close to current OCCT releases.
- **Helper layer: build123d** for convenient high-level operations (sketches,
  lofts, sweeps, fillets, text). It sits on OCP, so its shapes are plain
  `TopoDS_Shape` objects we can mix with raw OCCT calls. Command handlers may
  use build123d or OCP directly, but the model only stores OCCT shapes.
- **Fallback: pythonocc-core** (conda only). It ships a ready PySide6 viewer.
  If embedding the OCP viewer in Milestone 0 turns out to be fragile, we
  switch the binding; the rest of the plan does not change.

### 2.2 Second representation: meshes

Sculpting, scanned data, STL editing and implicit shapes are mesh problems,
not B-rep problems. The model has two body kinds:

- **Solid / Surface bodies**: OCCT B-rep. Exact. Default for engineering.
- **Mesh bodies**: triangle meshes, edited in `numpy`, booleans with
  `manifold3d` (robust, fast mesh CSG). `[done]` A mesh body's shape is one
  OCCT face that carries only a triangulation, so the model, IDs, picking,
  the tree and the views treat it like any body (docs/M6-mesh.md).

Conversion commands connect them: `TOMESH` (B-rep to mesh, by tessellation),
`TOSOLID` (mesh to B-rep as a faceted solid; true surface fitting is a
later stretch goal).

### 2.3 Viewport: OCCT's own visualization (AIS / V3d) inside PySide6

- OCCT's AIS viewer draws B-rep natively, with exact **sub-shape picking**
  (vertex, edge, face, solid) and highlighting. That is exactly what
  selection commands like `SEL, S, FACE, , 12` need. VTK or a custom OpenGL
  viewer would force us to rebuild face/edge picking ourselves.
- We embed it in a `QWidget` by passing the native window handle to
  `V3d_View` (the approach CQ-editor and FreeCAD-style viewers use).
- Meshes display through `AIS_Triangulation` / `MeshVS`. If high-poly
  sculpting is too slow there, Sculpt mode gets a dedicated `QOpenGLWidget`
  renderer (`moderngl`) in its milestone. That is a contained decision we
  make with measurements, not now.

### 2.4 Stack summary

| Concern | Choice |
|---------|--------|
| Language | Python 3.11+ |
| GUI | PySide6 (Qt 6) |
| Kernel | OCCT via OCP; build123d as helper |
| Viewport | OCCT AIS/V3d embedded in PySide6 |
| Mesh | numpy, trimesh, manifold3d |
| Implicit/equations | numpy expression evaluation, scikit-image marching cubes |
| Expressions | our own safe evaluator over Python's `ast` (no `eval`) |
| Constraint sketcher | our own small solver on numpy (chosen after a spike against planegcs and SolveSpace's solver; see docs/M3-sketcher.md) |
| File formats | native `.cmd` script + `.3dm`-style project zip; STEP, IGES, BREP, STL, OBJ, 3MF, glTF; other mesh files (VTK, PLY, OFF, Gmsh, Abaqus, Nastran) read with meshio |
| Tests | pytest; headless command tests need no GUI |
| Packaging | pip + `pyproject.toml`; PyInstaller bundles later |
| AI (last phase) | Claude API with tool use; the tools are our commands |

## 3. Data model

### 3.1 Shapes, objects, and reuse

The user's request "create objects, keep them as shapes, use them to create
new objects" maps to three levels:

| Level | What it is | Example |
|-------|-----------|---------|
| **Entity** | Topology inside a body: vertex (`KP`), edge (`LINE`), face (`AREA`), solid (`VOLU`) | face 12 of a block |
| **Body** | One shape in the model with an ID, name, color, layer, material | `VOLU 3` named `bracket` |
| **Part (definition)** | A named, reusable shape recipe: a sub-script with parameters | `PART, bolt, D=8, L=30` |
| **Instance** | A placed copy of a part with its own transform; editing the part updates all instances | `INST, bolt, 10,0,0` |

Bodies are always kept: a boolean like `SUBTRACT` produces a new body and,
by default, hides (not deletes) its inputs, so the inputs stay reusable.
`KEEP, ON|OFF` controls that.

### 3.2 IDs and the "topological naming" problem

Scripts refer to entities by number (`PICK, FACE, 12`). In history-based
CAD, numbers shift when an earlier step changes, and a reference that
silently moves to another face is the worst failure a modeler can have.
Our rules (the first five are built):

1. Bodies and entities get IDs that are stable through operations: after
   every operation, sub-shape IDs are carried forward using OCCT's history
   (`Modified`, `IsDeleted`), with a match by geometry where a builder
   reports nothing. A face that was split keeps its ID on the largest
   piece; faces that were merged keep the first one's ID.
2. Each history entry remembers the IDs it handed out and asks for them
   again on replay, including the ones a shorter run (a smaller loop count)
   did not reach. Project files store them, so open = the model as saved.
3. Every entity knows which history entry made it. A pick stores that with
   a fingerprint (type, place, size, direction). If the ID is gone, or now
   belongs to another entry's work, the pick is repaired from the
   fingerprint only when exactly one entity fits, and the entry is marked
   with a warning. It never guesses between look-alikes; it fails instead.
4. Scripts should prefer **geometric selection** over raw numbers:
   `SEL, S, FACE, NORMAL, 0,0,1`, `SEL, S, FACE, LOC, Z, 2`,
   `SEL, S, EDGE, OF, FACE`. Raw IDs remain available.
5. Named selections (`CM, top_faces, FACE`) give stable handles a script can
   reuse.

Still to do:

6. Name faces made by an operation by their parents ("the wall between
   face 6 of the plate and the side of hole 3"), so new faces of a boolean
   are found again even when the kernel returns them in another order. `[M3]`
7. Fingerprints for `SEL ..., ID` lists and named sets, and an option for
   the GUI to write a click as a geometric criterion when one identifies
   the entity uniquely (so plain scripts carry no raw IDs). `[M3]`

### 3.3 History = the command log

There is no separate feature tree file format. The command log *is* the
history. The **History panel** shows it as a tree (grouped by part and by
GUI action), and editing an old command re-runs the script from that point.
Undo/redo walks the log; snapshots every N commands make re-runs fast.

## 4. The command language

Comma separated, case-insensitive, one command per line.

```text
! comment
NAME, arg1, arg2, , arg4      ! empty args take defaults
```

### 4.1 Parameters and expressions

```text
W = 40                      ! scalar parameter
H = W/2
R = sqrt(W**2 + H**2)/4
P = (10, 0, 5)              ! point/vector
BLOCK, 0,0,0, W,H,5
```

Expressions support `+ - * / ** %`, `sin cos tan asin acos atan atan2 sqrt exp
log abs min max floor ceil`, `pi`, `e`, and model queries such as
`VOL(3)`, `AREA(12)`, `CENT(3).x`, `BBOX(3).zmax`, `NSEL(FACE)`.

### 4.2 Control flow and macros

```text
*DO, i, 1, 8
  CYL, 30*cos(i*pi/4), 30*sin(i*pi/4), 0, 3, 10
*ENDDO

*IF, W, GT, 30, THEN
  FILLET, EDGE, sel, 2
*ENDIF

*MACRO, drill, x, y, d          ! user macro = new command
  CYL, x, y, -1, d/2, 100
  SUBTRACT, VOLU, base, last
*END
drill, 10, 10, 6
```

`*PY ... *ENDPY` runs a Python block with the model API, for anything the
language can't express. It is off by default for scripts from others.

### 4.3 Command families (initial list)

| Family | Commands |
|--------|----------|
| Points/curves | `K` (keypoint), `LINE`, `ARC`, `POLYLINE`, `SPLINE` (interpolate), `NURBSCRV` (control points, weights, knots), `HELIX`, `CURVE, PARAM, x(t), y(t), z(t), t0, t1`, `JOIN` |
| Profiles | `CIRCLE`, `ELLIPSE`, `RECT`, `POLYGON`, `SLOT`, `STAR`, `AIRFOIL` (NACA 4-digit), each on any plane |
| Sketch | `SKETCH, plane` ... `ENDSKETCH`, `RECT`, `POLYGON`, `SLOT`, `TEXT`, constraints `CON, COINCIDENT/PARALLEL/TANGENT/DIST/ANGLE/RADIUS ...`, `TRIM`, `OFFSET2D` |
| Primitives | `BLOCK`, `CYL`, `CONE`, `SPHERE`, `TORUS`, `WEDGE`, `PRISM`, `PYRAMID`, `TUBE`, `CAPSULE` |
| Sketch-based features | `EXTRUDE`, `REVOLVE`, `HOLE`, `RIB`, `THREAD` |
| Shapes on curves | `LOFT`, `SWEEP` (with twist/scale/offset laws, several profiles to morph, rails), `PIPE`, `SWEEPVOL`, `FLOW`, `BEND`, `TWIST`, `TAPER` (see 5.2) |
| Surfaces | `NURBSSRF` (control net), `SURF, PARAM, x(u,v), y(u,v), z(u,v)`, `LOFTSRF`, `NETWORK` (curve network), `PATCH` (fill boundary), `BLENDSRF`, `PIPE`, `OFFSETSRF`, `EXTENDSRF`, `SEW` (surfaces to solid), `REBUILD` |
| Implicit / equations | `IMPLICIT, name, f(x,y,z), box [, step]` (shape is where f ≤ 0), `GYROID`, `LATTICE`, smooth blends `SMIN`/`SMAX`/`SDIFF` inside the field (done, M6b) |
| Booleans | `UNION` (`VADD`), `SUBTRACT` (`VSBV`), `INTERSECT` (`VINV`), `SPLIT` (body by plane/surface/body), `IMPRINT`, `GLUE` |
| Modify | `FILLET`, `CHAMFER`, `SHELL`, `DRAFT`, `OFFSET`, `THICKEN`, `DEFEATURE`, `PUSHPULL` (face), `MOVEFACE`, `DELFACE`, `REPLACEFACE` |
| Transform/pattern | `MOVE`, `ROTATE`, `SCALE`, `MIRROR`, `ALIGN`, `COPY`, `ARRAY, LINEAR/POLAR/PATH` |
| Freehand | `STROKE` (recorded mouse points), `KNIFE` (cut by stroke projected through view), `SLICE` (by plane), `SCULPT, brush, ...` |
| Mesh | `TOMESH`, `TOSOLID`, `REMESH`, `SIMPLIFY`, `SMOOTH`; `UNION`/`SUBTRACT`/`INTERSECT` run on triangles when a mesh body is in them `[done]` |
| Parts/reuse | `PART ... ENDPART`, `INST`, `EXPLODE`, `LIB, SAVE/LOAD` |
| Selection | `SEL, S/R/A/U/ALL/NONE/INVE, type, criterion, ...`, `CM` (named set), `CMSEL`, `PICK` (the raw GUI pick) |
| Display/view | `VIEW, ISO/TOP/FRONT/...`, `ZOOM`, `FIT`, `SHOW`, `HIDE`, `COLOR`, `LAYER`, `SECTION`, `ANALYZE, ZEBRA/CURVATURE/DRAFT` |
| Measure | `DIST`, `ANGLE`, `MASSPROP`, `CHECK` (validity) |
| Files | `SAVE`, `OPEN`, `IMPORT`, `EXPORT, STEP/IGES/STL/OBJ/3MF/GLTF`, `RUN, file.cmd`, `LOG, ON/OFF` |
| Session | `UNDO`, `REDO`, `CLEAR`, `/UNITS`, `/TOL` |

Every GUI tool is a thin form that fills in one of these commands. The
command it built is shown in the form before it runs, and lands in the
History panel and the log, so users learn the language by using the GUI
(docs/M2-forms.md).

### 4.4 Selection in detail

```text
SEL, S, VOLU, ID, 3              ! select body 3
SEL, R, FACE, NORMAL, 0,0,1      ! reselect: keep faces facing +Z
SEL, A, EDGE, LENGTH, GT, 10     ! add edges longer than 10
SEL, S, FACE, BOX, 0,0,0, 10,10,2
SEL, S, EDGE, OF, FACE, sel      ! edges of the selected faces
CM, top, FACE                    ! save as named set
FILLET, EDGE, sel, 1.5           ! "sel" = current selection
```

A viewport click emits `PICK, FACE, 12` which the processor translates into
the most robust equivalent (`SEL, S, FACE, ...`) when it writes the log.

## 5. Feature catalogue

Grouped by what the user asked for. `[M#]` is the milestone that delivers it.

### 5.1 Basic and complex shapes
- Primitives with full parameters and placement `[M1]`
- 2D sketches with constraints, then extrude/revolve `[done]`; trim, extend, fillet, offset, mirror, pattern and projected edges in a sketch `[done]`
- Sweeps, lofts, pipes and helices, with shapes that change along the path: see 5.2 `[M2]`/`[M4]`/`[M5]`
- Text and logos: `TEXT` from any font, flat or solid letters `[done]`

### 5.2 Shapes on curves: sweeps, lofts and morphing

The idea: take a section (a profile), move it along a curve, and let it
change on the way: turn, grow, shrink, stretch, or turn into a different
shape. Every one of these is a command, so a blade, a horn, a handrail or a
spring is a short script whose numbers you can change later.

**Curves to sweep along (paths)** `[M2]`
- `LINE`, `ARC` (3 points or center/angle), `POLYLINE`, `SPLINE` through points (with optional end tangents)
- `HELIX`: radius, pitch, turns, left/right hand, taper angle, and a pitch law for springs with closer coils at the ends
- `CURVE, PARAM, x(t), y(t), z(t), t0, t1`: any equation, fitted to an exact B-spline
- `JOIN` curves into one path; `EDGE` of a body as a path (sweep along a model edge)

**Profiles (the moving shape)** `[M2]`
- `CIRCLE`, `ELLIPSE`, `RECT` (with corner radius), `POLYGON` (n sides), `SLOT`, `STAR`, `AIRFOIL` (NACA 4-digit: chord, camber, thickness)
- Each one is placed on any plane (origin, normal, and an X direction), and a closed `POLYLINE`/`SPLINE` is a profile too
- Later: any sketch from the sketcher `[M3]`; text outlines are faces from `TEXT` `[done]`

**Loft: a smooth shape through sections** `[M2]`
- `LOFT` through 2 or more sections: smooth (one B-spline surface) or ruled (straight between sections)
- Closed lofts that loop back to the first section (a ring with a changing section)
- Sections with different shapes and point counts (circle to square to star); start points matched so the surface does not twist by accident
- Solid or open surface; caps on or off
- Loft along a spine curve, so the sections follow a curved center line (`SPINELOFT`) `[done]`
- Loft with guide curves that the side of the shape must pass through (`LOFT, ..., GUIDE, g1, g2`) `[done]`

**Sweep: drag a profile along a path** `[M2]`
- `SWEEP, profile, path`: exact sweep of one profile
- Orientation modes: follow the curve (Frenet), minimal twist (the default; no flips on 3D curves), fixed direction, keep a chosen "up" direction (binormal), and follow a surface's normal (`NORMAL`, with `PROJECT` to lay the path on the surface) `[done]`
- Sharp or rounded corners on polyline paths
- Solid or open (a surface), and keep the profile perpendicular to the path or as placed

**Laws: how the profile changes along the path** `[M2]`
- A law is an expression in `t`, where `t` goes from 0 at the start of the path to 1 at the end, so it can use parameters and any math:
  - twist: `"40 - 32*t"` degrees
  - scale: `"1 - 0.5*t**2"`, or separate X and Y scales to stretch the section
  - offset: slide the profile off the path (a cam track, an S-shaped duct)
- Laws can also be a table of stations (`TABLE(t, t0, v0, t1, v1, ...)`), joined smoothly without overshoot; this is what the GUI edits `[done]`
- Laws work in `SWEEP`, `PIPE`, `HELIX` (pitch) and `ARRAY, PATH` (spacing, scale, turn)

**Morph: the profile turns into other shapes on the way** `[M2]`
- `SWEEP` with several profiles placed at stations along the path: a round duct that turns square, then flat; a blade root that turns into an airfoil
- Laws (twist, scale) apply on top of the morph

**Rails: curves that steer the shape** `[done]` (`RAILSWEEP`)
- One guide rail: the profile turns so a chosen point always touches the rail (a twisted handrail, a ribbon)
- Two rails: the profile is turned and scaled so it spans both rails (a wing between its leading and trailing edges, a ship hull, a guitar neck)
- Rails and laws combine: rails set the size, a law adds thickness change

**Pipes, springs and threads**
- `PIPE, path, r`: round tube along any curve, solid or hollow (wall), with a radius law `[M2]`
- Springs: `SPRING` with closed and ground ends; any other pitch law with `HELIX` + `PIPE` `[done]`
- Threads: `THREAD` cuts real ISO metric threads, outside and inside, coarse or any pitch `[done]`

**Shape follows a curve (deformers)** `[M5]`
- `FLOW`: bend an existing body so it follows a curve (a straight text or pattern wrapped onto a path)
- `BEND`, `TWIST`, `TAPER`, `STRETCH` of whole bodies, with laws; exact on B-rep where OCCT allows, through NURBS approximation otherwise; meshes always
- `SWEEPVOL`: the volume a moving tool body sweeps through (a cutter path, a keyway), so it can be cut away with `SUBTRACT`

**Patterns along a path** `[M2]`
- `ARRAY, PATH`: copies along a curve, keeping their orientation to the curve, with count or spacing, and laws for scale and turn (chain links, a spiral staircase, beads)

**Working with it in the GUI** `[done]` (the sweep editor, for `SWEEP`)
- Pick the profile and path in the viewport, and a preview appears
- A slider moves a "ghost" section along the path, showing what it looks like at that `t`
- Handles at stations set twist and scale by dragging (on the law graphs); Apply edits the law table through `HIST, EDIT`, so the command stays the source of truth. Later: the same editor for `MORPH`, `PIPE` and `RAILSWEEP` laws, and handles in the 3D view
- A small graph shows each law over `t`

### 5.3 NURBS and freeform
- NURBS curves: control points, degree, weights, knot editing; interpolate through points `[done]` (`NURBS`, `MOVEPT`, `WEIGHT`, `KNOT`, `DEGREE`; `SPLINE` interpolates)
- NURBS surfaces: from control net (`NSURF`), loft, network of curves (`NETWORK`), patch/fill with G0/G1/G2 to neighbouring surfaces (`FILL`) `[done]`; blend between surfaces with G1/G2 continuity (`BLEND`), extend (`EXTEND`), offset (`OFFSET`), trim by curves (`TRIM`) `[done]`
- Control-point editing in the viewport (drag points, each drag is a `MOVEPT` command) `[done]` (the Control points button, `CPOINTS`)
- Rebuild/reparameterize, sew surfaces into solids `[done]` (`REBUILD`, `SEW`)
- Analysis: zebra stripes, Gaussian/mean curvature map, draft angle (`ANALYZE`, in words and colours) `[done]`

### 5.4 Equation-based geometry
- Parametric curves `x(t), y(t), z(t)` and surfaces `x(u,v), y(u,v), z(u,v)`, fitted to NURBS so they become exact geometry usable in booleans (`CURVE, PARAM`, `SURFACE, PARAM`; closed surfaces become solids) `[done]`
- Implicit shapes `f(x,y,z) ≤ 0` (gyroids, metaballs, superquadrics), meshed by marching tetrahedra; smooth blends between them `[done]` (`IMPLICIT`, `SMIN`/`SMAX`; LANGUAGE.md section 26)
- Lattice infill of a solid (gyroid, Schwarz, diamond, cubic, BCC, octet), with an optional solid skin `[done]` (`LATTICE`)
- Driven dimensions: any number in any command can be an expression of parameters `[M2]`

### 5.5 Reuse and operations
- Bodies kept and reusable after booleans (`KEEP`) `[M2]`
- Parts with parameters, instances that follow the definition, part library across projects `[M4]`
- Booleans, split, imprint `[M2]`; fillet, chamfer, shell, draft, offset, thicken `[M3]`
- `SPLIT` by a plane or a body, `HOLE` (simple, counterbore, countersink, drill point; one command instead of cylinder plus subtract), `SHELL`, `DRAFT`, `OFFSET` `[done]`; threaded holes (`HOLE` then `THREAD`) `[done]`; variable-radius and face fillets `[M3]`
- Faster repeated cuts: `SUBTRACT, a, SEL` takes many tools in one kernel call; `ARRAY ... CUT, target`; patterns of features (`PATTERN` repeats what the last steps did, not just a body) `[done]`
- Direct editing: push/pull faces (`PUSHPULL`), delete faces and close the gap (`DELFACE`), great on imported STEP `[done]`; move a face by a vector (`MOVEFACE`), replace a face (`REPLACEFACE`) `[done]`
- Patterns: linear, polar, along a path `[M2]`

### 5.6 Freehand
- **Knife**: draw a stroke on screen, it is projected through the view and cuts or splits the body (`KNIFE`) `[done]` (the Knife button; also a slot of a given width, and a closed stroke cuts out its inside; solids and mesh bodies)
- **Freehand sketch**: draw a closed stroke on a face or plane, it is fitted to a spline, then extruded as cut or boss `[done]` (the sketcher's Freehand tool writes `SSPLINE`; sketch splines can be dragged and constrained by their points)
- **Sculpt mode** on mesh bodies: draw, clay, inflate, smooth, flatten, crease, grab, mask; symmetry; remesh/dynamic resolution `[M7]`
- Every brush stroke is logged as `SCULPT, brush, radius, strength, stroke-file-ref`, so sculpting is replayable too (stroke points saved in the project zip)

- Configurations: named sets of parameter values for one model (sizes of a family of parts), switchable from the Parameters panel and from the batch runner `[M4]` `[done]` (`CONFIG`, `USECONFIG`, `-C`; and `BOM`, the parts list)

### 5.8 AI assistant (last)
- Chat panel that explains any command, turns plain language into a command script, explains errors, and can read the current model state through query commands `[M9]`
- The AI never edits the model directly; it proposes commands, the user sees and accepts them, and they run through the same processor and log.
- **Tools made for the AI** (full design in docs/M9-ai-tools.md). The assistant checks its work with exact text queries instead of looking at pictures, which saves tokens and gives stronger answers (a picture cannot tell a 6.0 mm hole from a 6.4 mm one). Pictures stay as a fallback. The tools, in six groups:

| Group | Tools | What they give the AI |
|-------|-------|-----------------------|
| Learn the language | `find_commands`, `command_help`, `search_docs` | arguments, defaults, examples and errors from the command registry and LANGUAGE.md, on demand, so the system prompt stays small |
| Read the model | `model_summary`, `describe_body`, `describe_entities`, `around`, `history`, `parameters`, `sketch_state`, `user_context` | bodies, sizes, validity; features a person would name (holes with size, depth and pattern, fillets, pockets, symmetry), from the history first and the geometry otherwise; what the user has selected or is pointing at |
| Probe space | `probe_ray`, `probe_point`, `section_profile`, `outline`, `measure`, `wall_thickness` | where material is: ray hits, inside or outside, a cut through a body as loops of lines and arcs (a stack of cuts reads like a scan), a silhouette as a 2D path |
| Try in a sandbox | `sandbox`, `lint`, `run`, `diff`, `check`, `vary`, `round_trip`, `check_design` | a copy of the model to run scripts in, with per-step results and diffs; expectations checked exactly (`ASSERT`, a new command also usable in scripts and the regression corpus); a parameter swept over values; history edits undone and checked for stable references |
| Hand over | `propose`, `ask_pick`, `highlight`, `selector_for`, `preview_selection` | a card with the commands, summary, diff and passed checks plus a ghost preview, which the user accepts as one undoable step; asking the user to click instead of guessing; robust `SEL` criteria in place of raw IDs |

- Rules for all of them: each wraps a command a person can also type, so it runs headless and is unit tested; answers are compact JSON, rounded to the tolerance, paged, in stable ID order, and carry the model revision (so the AI can ask only for what changed); errors come with a hint; the tool list is fixed for a chat so its definitions can be cached.
- Built so far (M9a, first part): `ASSERT` with `VALID`, `PIECES`, `NFACES`, `HOLES`, `SYMMETRIC`; `DESCRIBE` (with round holes found from the geometry); `SELFOR`; `LINT`; `DIFF`; the sandbox and a JSON tool list (`python -m modeler tool ...`). M9b first part: `PROBE` (rays, points), `PROFILE` (a cut as text), `THICK` and `MINWALL`, and the `vary` and `round_trip` tools. See docs/M9-ai-tools.md section 8.
- Next (plan, PLAN.md items 43 to 47, docs/M12-assistant-skills.md): skill files that teach whole workflows to the assistant, the MCP server and people (as guides), analysis answers as data with queries for `ASSERT`, the remaining M9 tools, help when a step fails, and a bigger benchmark.
- Build order: **M9a** tools without AI (`DESCRIBE`, `ASSERT` and new queries such as `HOLES`, `VALID`, `PIECES`, `MINWALL`, `LINT`, `DIFF`, the sandbox), useful early for the regression corpus and for GUI picks written as criteria; **M9b** seeing without pictures (feature recognition, `PROBE`, section profiles, outlines, wall thickness, design checks, parameter sweeps); **M9c** the chat panel, proposal cards, picking, rendering, the API connection, and a benchmark of modelling requests that records success, tokens and pictures used. ### 5.9 Model tree and right-click menu (after release 0.2.0)

Asked for by the user after running 0.1.0 on Windows: today a right click on
a picked body does nothing, and there is no list of what the model holds.
This is built right after release 0.2.0, before M6 (milestone **M10** in
section 7). Like everything else, the tree and the menu only send commands.

**What it should do**

- **A model tree** in a left dock: every body, grouped the way a person
  thinks of the model. Parts and their instances (a bolt part with its 8
  placed bolts), loose bodies, sketches, datums (planes, axes, points, work
  planes), named sets, and layers as an optional grouping. Each row shows the
  name, an eye for shown or hidden, a faded marker, the colour, and a warning
  or error badge taken from the history. Picking in the tree selects in the
  viewport and the other way round; a double click zooms to the item.
- **A right-click menu**, the same in the tree and on a body clicked in the
  3D view: Hide, Show, Show only this (isolate), Fade this, Fade all others
  (this one stays solid), Show everything, plus Rename, Colour, Layer,
  Material, Zoom to, Delete, Edit history of this, and for a part instance
  Edit part and Explode.
- **Edit from the tree.** Selecting an item, for example a screw, lists every
  history step that made or changed it, in order (for a bolt placed from a
  part: the part's head, shank, `THREAD` with its pitch and length, and the
  `INST` that placed it). Each step opens in its fill-in form, or in the
  sweep editor for a sweep, and the parameters it uses are shown with their
  values, so changing the helix pitch or the diameter is one edit that
  re-runs the model. For a part instance the list shows the instance's own
  values (`D`, `L`) and the part's recipe, with a choice of changing this one
  instance or the part (which updates every instance).

**What exists to build on**

- History panel (`gui/main_window.py`, `HistoryPanel`): its right-click menu
  already has Edit, Edit in form, Sweep editor, Insert before, Suppress,
  Delete, Sizes of sketch, Roll back and Make a part from steps. The tree's
  step list reuses these actions.
- Command forms with edit-step (`gui/forms.py`, `gui/form_dialog.py`,
  `open_form(..., edit_row)`):
  every command already opens in a form that writes `HIST, EDIT`.
- Visibility: `HIDE`, `SHOW`, `ISOLATE` (bodies, `SEL` or a layer), layers
  on, off and locked, the Layers panel (`gui/layer_panel.py`), and the
  model's `visibility` event that the viewport already listens to.
- See-through drawing: `Model.display_transparency` (today only from a
  material, such as glass), so fading is a second source for the same value.
- Parts and instances (`commands/part_handlers.py`): `Model.instances` maps
  each placed body to its part and values; `*PART`, `INST`, `EXPLODE`,
  `LIST, PARTS`.
- Stable IDs and origins (`core/model.py`): every body, face, edge and vertex
  knows the history entry that made it (`Model.origin`), and a body made
  from others keeps its ID and name, so the tree's rows survive edits.

**What is new**

1. Done (M10a): `FADE, b|SEL|OTHERS[, amount]`, `UNFADE, b|ALL` and
   `DISPLAY, HIDE|SHOW|ONLY|ALL|MODEL`: a view state kept on the model next
   to `hidden`, drawn through `display_transparency`. Hide,
   show, fade and isolate from the menu become view steps: saved with the
   project but not history entries, so clicking around does not fill the
   history. (`HIDE` and `SHOW` are history entries today; scripts that use
   them keep working.)
2. Done (M10a): a right click without dragging opens the menu in the viewport (a right
   drag still pans). The menu acts on the body under the cursor, or on the
   whole selection when the cursor is on a selected body.
3. Done (M10b): lineage: each history entry records which bodies it read and which it
   made or changed. This is the same record that "skip entries whose inputs
   did not change" needs (risk 3), so both are built on it. A body's list of
   steps is its lineage walked back through its inputs.
4. Done (M10b): the tree widget: built from model events and history refreshes, kept in
   step with the selection, its layout saved with the window.
5. Done (M10c): an item panel under the tree: the steps of the picked item
   with Edit buttons (a line inside a `*PART` recipe or a loop opens in its
   own form and is written back into that entry), and the parameters they
   use. For an instance the panel says that a line of the part's recipe
   changes every copy. Left for later: changing one instance alone when a
   loop placed several (it needs the instance pulled out of the loop).
6. Done (M10c): tests that run headless: the new commands, lineage on the example scripts
   (bolted plate, threaded bolts, the car), and GUI tests for the tree and
   the menus under a virtual display.

**Pull requests** (about three items each)

- **M10a:** `FADE`/`UNFADE` and view steps (1), the viewport right-click
  menu (2), and the same body actions on History rows. Usable on its own:
  hide, show and fade by right click.
- **M10b:** lineage per history entry (3), the model tree dock (4), its
  right-click menu and two-way selection.
- **M10c:** the item panel with each step's form and parameters (5),
  instance or part editing, tests on the example scripts (6), and the
  USER-GUIDE.md and LANGUAGE.md sections.

Exit test: open the threaded bolts example, right-click a bolt in the view
and fade the others, find the same bolt in the tree, open its `THREAD`
step, change the pitch, and see every bolt of that part update.

### 5.10 Separate part and assembly design (after the model tree)

Asked for by the user after 0.2.0: design one part on its own, with only that
part loaded, and design an assembly separately by adding the finished parts.
This is milestone **M11**, built right after M10 (section 5.9) and before
M6, because "Open part" and "this copy or the part" use the model tree and
the right-click menu. Like everything else, it only sends commands.

**What exists today**

- "Make a part from steps" in the History panel (`HIST, PART`) turns steps
  into a `*PART` block with its own sizes (`D`, `L`); `LIBSAVE` writes the
  block to a `.cmd` file in the part library; `LIB, LOAD` and `INST` place
  copies in another project, and editing the block there updates every
  copy.
- The whole `*PART` block is one history entry, so its inner steps can only
  be edited as text; opening a part file shows nothing until something
  places it.
- A saved project keeps a frozen copy of each part file it loaded, and a
  reopened project reads that copy first, so later edits of the part file
  never reach the assemblies that use it.
- Copies are placed by position and angle only; there are no mates.

**What is new**

1. Done (M11a): **Part documents.** File > New part and Open part. A part document is a
   normal model whose steps show in History (each opens in its form or the
   sweep editor), whose sizes show in the Parameters panel marked as the
   part's inputs, with a default for each. Saving writes the part file: the
   steps wrapped into one `*PART` block, with the same code as
   `HIST, PART`. Opening a part file unwraps its block back into steps.
   A part file that holds several parts asks which one to open.
2. Done (M11b): **Linked parts in an assembly.** `LIB, LINK, file` (next to `LIB, LOAD`)
   reads the part file itself on every open and rebuild, not a frozen copy.
   When the file changed since the last run, every copy of the part is
   rebuilt and the assembly says so ("bolt updated from bolt.cmd"). `SAVE`
   still keeps a copy in the project, used only when the file is missing,
   with a warning. `LIST, PARTS` shows each part's file and whether it is
   linked or loaded.
3. Done (M11a, M11b): **Editing a part from the assembly.** In the tree and the right-click
   menu, a copy of a linked part offers Open part, which opens the part
   document in its own window. Saving it there updates the assembly
   window. Done (M11a): for a part defined inside the project, Edit part
   opens the same part view on its `*PART` block and writes `HIST, EDIT`
   back.
4. Done (M11c): **Mates.** `MATE, a, b, COINCIDENT|CONCENTRIC|DISTANCE|ANGLE [, value]`
   between faces, edges or axes of two copies, solved in order as placement
   steps (each moves the second copy; a full solver comes later if needed).
   The result is checked with `CONTACT` and `CLEARANCE`, and a mate that
   cannot be met is an error that names both items.
5. Done (M11a-c): Tests that run headless: part document round trip (open, edit a step,
   save, same volume), a linked part changed on disk updates every copy, the
   missing-file fallback, each mate kind on the bolted plate example, and GUI
   tests for New part, Open part and the menu entry.

**Pull requests**

- **M11a:** part documents (1), Edit part for parts inside a project (3,
  second half), the round-trip tests.
- **M11b:** linked parts (2), Open part from the tree and the menu (3), the
  file-changed tests.
- **M11c:** mates (4), their tests, and the USER-GUIDE.md and LANGUAGE.md
  sections for parts and assemblies.

Exit test: make a bolt in a part document and save it, start an assembly,
link the bolt and place eight copies on a plate with concentric and
coincident mates, then open the bolt from one copy, change its length, save,
and see all eight copies in the assembly update.

## 6. Architecture

```
 ┌───────────── gui/ (PySide6) ─────────────┐
 │ toolbars & forms → build command text    │
 │ command line, log, history tree, params  │
 │ viewport/ (OCCT AIS)  → PICK commands    │
 └──────────────┬───────────────────────────┘
                │ text
        ┌───────▼────────┐
        │ commands/      │ lexer → parser → expression eval → registry
        │ processor      │ → handler(args, model) → result
        └───────┬────────┘
                │ API calls only
        ┌───────▼────────┐        ┌────────────┐
        │ core/ model    │◄──────►│ geometry/  │ OCCT wrappers, mesh ops,
        │ bodies, IDs,   │        │            │ implicit, NURBS fitting
        │ selection, undo│        └────────────┘
        └───────┬────────┘
                │ change events (body added/changed/removed)
                ▼
        viewport refresh
```

Rules:

- The model knows nothing about Qt. The whole core runs headless, so every
  command is unit-tested without a window, and scripts can run in batch mode
  (`python -m modeler run bracket.cmd --export bracket.step`).
- Handlers register themselves with a decorator that declares argument names,
  types, defaults and help text. The same metadata drives the parser, the
  GUI forms, `HELP, CMD`, autocomplete, and the AI's tool list.
- Long history rebuilds run in a helper process (the kernel keeps Python's
  lock, so a thread would not help) with a progress bar and cancel; see
  docs/rebuild-helper.md.

Code layout:

```
modeler/
  commands/      parser.py, expr.py, registry.py, processor.py, handlers/*.py
  core/          model.py, body.py, ids.py, selection.py, history.py, units.py
  geometry/      occ_ops.py, nurbs.py, param_fit.py, implicit.py, mesh_ops.py, io.py
  gui/           main_window.py, command_line.py, log_panel.py, history_tree.py, forms/
  viewport/      occ_view.py, picking.py, overlays.py, sculpt_view.py
  ai/            (M9)
scripts/         examples (*.cmd)
tests/
```

## 8. Risks

Ranked by how much each one decides whether the app can be trusted for real
work. Numbers were measured in November 2026 on the code after M2.

| # | Risk | State | What is built | What is left |
|---|------|-------|---------------|--------------|
| 1 | **References break when history is edited** (the topological naming problem). A pick that silently moves to another face makes every edited model suspect. | Much reduced | IDs carried through operations; IDs kept per entry, also when a loop shrinks and grows; IDs saved in project files; picks know which step made the entity and are repaired by fingerprint only when the match is unique, with a warning | Parent-based names for faces made by booleans; fingerprints for ID lists and named sets; GUI picks written as criteria (3.2, items 6 and 7) |
| 2 | **The kernel returns bad shapes without saying so.** Measured: an oversized fillet gave an invalid body, a subtract that removed everything gave an empty body, a union left seams. | Much reduced | Every boolean and blend is checked; empty and invalid results are errors with the model unchanged; oversized fillets name the size that works; retry with a tolerance; seams merged; `CHECK`, `HEAL`, `CLEAN`; `HOLE`, `SPLIT`, `SHELL`, `DRAFT` and `OFFSET` are checked the same way (a shell too thick names the thickest wall that works); shapes made from curves get a section test that catches tight bends, sharp corners, overlapping turns and crossing sections (the kernel calls those valid), and a corpus of 22 hard cases plus every example runs in CI | Faces of a loft that cross between its sections are only found by `CHECK, b, SELF` (too slow to run every time) |

    `PUSHPULL` or `MOVEFACE`. The assistant gets nothing new to learn: the
    same commands, plus `HANDLES` to list what a drag would change.
    *Done (gui/drag_handles.py, Home > Drag handles, `HANDLES`): arrows and
    rings on a body, a pull arrow and small arrows on faces, grid and 5 degree
    snapping, typed values, Esc; a jointed body drags its linkage. Snapping to
    vertices and edges is left for later.*
69. **Joints that stay solved** (P0): `JOINT, kind, a, b [, limits]` with FIXED,
    REVOLUTE, SLIDER, CYLINDRICAL, BALL, PLANAR, GEAR, RACK, SCREW and BELT,
    and a solver that keeps every joint true after any edit. Dragging a part
    moves the linkage within its limits; `DRIVE` and `MOTION` run on joints
    as well as parameters. Joints show in the tree, with a right-click menu
    to flip, suppress or edit. `JOINTS` lists each joint, its free motions
    and any that fight, as data. Mates stay as one-off placements.
    *Done (core/joints.py, `JOINT`, `JOINTS`): every kind and coupling, held
    values as parameters (DRIVE, MOTION), limits, chains and closed loops,
    a MOVE or ROTATE of a jointed body moves the linkage. Joint rows in the
    tree with flip and suppress are left for later.*
70. **Editing imported parts without history** (P0): `FEATURES, b` finds the
    holes, fillets, chamfers, bosses, pockets and patterns on a body with no
    history (STEP, IGES) and lists them with sizes. Then resize or remove
    them in bulk: `DEFEATURE, b, FILLETS, LT, 2`, `RESIZE, b, HOLES, EQ, 6, 8`.
    In the GUI the found features show in the tree under the body; right
    click gives Select similar, Change size, Remove. Select similar also
    works on any picked face or edge (same radius, same type, same size).
    *Done (geometry/found.py, `FEATURES`, `DEFEATURE`, `RESIZE`, `SEL ...
    LIKE` and `FEATURE`, right-click Select similar / Change size / Remove,
    skill imported-parts): holes with bottoms and counterbores, rounds,
    chamfers, rows and rings of holes. Bosses and pockets, and feature rows
    in the tree, are left for later.*
71. **Sheet metal from an imported bent part** (P1): `TOSHEET, b` finds the
    thickness, the bends and their radii in a solid that was not made with
    `SHEET`, so `UNFOLD`, `SHEETINFO` and `FLANGE` work on it. Refused with a
    plain reason when the walls are not of one thickness.
    *Done (geometry/sheet_detect.py, `TOSHEET`, skill sheet-metal): a flat
    base with flanges bent straight off it, up or down, at any angle and
    radius. Bends off other bends, and walls of several thicknesses, are
    refused with the reason (the flat pattern must explain the volume).*
72. **More on drawing sheets** (P1): balloons that follow the parts list,
    a parts-list table, a hole table (position, size, thread, depth) and a
    revision table, all made again when the model changes. Added by command
    (`DRAWSHEET` options) and by right click on a view.
    *Done (geometry/sheet_tables.py, `DRAWSHEET` tables, `SHEETTABLE`,
    `REVISION`, `SHEETDATA`, right click in the 3D view): parts list with
    balloons, hole table with tags (one letter per kind of hole; the thread
    from a NOTE on the hole), revision table; the newest revision is the
    title block's REV.*
73. **Sizes and tolerances in STEP** (P1): `NOTE` sizes, hole notes,
    geometric tolerances and datums written to STEP (AP242) so other
    programs read them, and read back when such a file is imported.
    *Done (geometry/step_pmi.py, commands/pmi_notes.py, `EXPORT, STEP`,
    `IMPORT, STEP`): sizes, diameters with fits (found again from their
    limits), all GD&T kinds with round zones and up to three datums. Plain
    text notes stay in the project; a datum no tolerance uses is written but
    not read back.*
74. **Plug-ins** (P1): a folder where people put their own Python commands
    (one file each, with a form, help and a skill made from their arguments),
    a plug-in list in Preferences to turn them on or off, and a check that a
    plug-in cannot change the model except through commands.
    *Done (modeler/plugins.py, `PLUGINS`, Preferences > Plug-ins): one
    Python file per plug-in with `plugin_command`; forms, help and an
    assistant skill come from its arguments; a plug-in that changes the
    model without commands is stopped and its change undone; errors name
    the file and line; an example (`BOLTRING`) can be added from
    Preferences.*
75. **Mouse styles and shortcuts** (P1): orbit, pan and zoom styles that copy
    the common CAD programs, picked in Preferences, and a shortcut editor for
    every command and button, saved with the user's settings.
    *Done (viewport/mouse_styles.py, gui/shortcuts.py, Preferences > Mouse
    and keys): five styles (this app's, middle button orbits, middle
    button pans, right button orbits, Blender-like) and an invert-wheel box;
    the status bar says what each drag does. The shortcut editor lists every
    menu item, toolbar button and command form, warns about keys used twice
    and resets; keys are kept by English names, so they survive a language
    change.*
76. **The window in other languages** (P2): every menu, button, form label
    and message ready for translation (Qt translations), the first language
    files, and a test that no text is left out. Commands stay in English, so
    scripts work in every language.
    *Done (modeler/i18n, Preferences > Look > Language): Qt Linguist files
    for German and Spanish; every menu, button, tab, dialog and form label
    is translated, and tooltips and help are in the files for translators
    (English until translated). Windows and menus are translated as they
    open, and switching language works at once. `python -m modeler.i18n
    update` adds new texts; a test fails when a text is missing or a label
    is untranslated. Commands, their output and the assistant stay English.*
77. **Point clouds** (P2): import .ply, .xyz, .pts and .e57 points as a point
    body (thinned for speed), pick a patch of points and fit a plane,
    cylinder, sphere, cone or freeform surface to it (`FITPOINTS`), with the
    deviation reported like `DEVIATION`.
    *Done (geometry/pointcloud.py, `IMPORT` XYZ/PTS/E57/PLY, `TOPOINTS`,
    `FITPOINTS`): a point body is loose vertices (each point can be
    picked), thinned evenly to at most 200,000 points; E57 is read
    directly (float and scaled-integer points, scan poses). `FITPOINTS`
    fits a plane, cylinder, sphere, cone or freeform face (AUTO: the
    simplest that fits) to the points around a picked point, makes the face
    and reports the sizes and the deviation; `DEVIATION` measures clouds
    too; the right-click menu on a cloud offers the fits.*
78. **Shrinkwrap** (P3): `WRAPSKIN, b|ALL, gap` puts one clean closed skin
    around a messy mesh or a whole assembly (holes, overlaps and loose bits
    closed over), for printing and for quick outside shapes.
    *Done (geometry/shrinkwrap.py, `WRAPSKIN`, right click > Wrap in one
    closed skin): a grid of distances to the bodies' surfaces, the outside
    found by flooding from the border, the skin pulled back to the surface
    and meshed into one closed mesh body; holes and gaps under about twice
    the gap close, far parts stay separate pieces. Works on meshes, exact
    bodies and point clouds.*
79. **Fixing clashes** (P3): from a `CLASH` result, one click (or
    `CLASHFIX, a, b, CUT|MOVE`) cuts the overlap out of one part or moves it
    clear, with a preview first.
    *Done (`CLASHFIX`, right click with two bodies picked): CUT takes the
    other part's shape (grown by a clearance when asked) out of the first;
    MOVE finds the shortest move along the axes or straight away that
    clears it (to a round number when one works). `PREVIEW` as the last
    word marks the cut-away piece or the moved part and changes nothing (not
    kept in the history). `CLASH` says how to fix what it finds.*
80. **Getting a part ready for analysis** (P2): geometry only, for export to
    the separate meshing and solver app; no meshing or solving here.
    `MIDSURFACE, b` makes the middle surface of a thin part with the
    thickness kept on each face (for shell models), and `BEAMS, b` the centre
    lines of frame members with their profiles (for beam models).
    *Done (`MIDSURFACE`, `BEAMS`; right click "Analysis: ..."; the
    analysis-prep skill): MIDSURFACE pairs each face with the face straight
    across the wall, offsets one side by half the thickness (as one sheet
    when the thickness is the same, so walls meet at corners) and keeps the
    thickness per face, written to STEP as face names. BEAMS gives one line
    per member, joined at shared ends, with area, second moments, torsion
    constant and main direction.*
81. **Flow and enclosure volumes** (P2): `FLUIDVOLUME, b, caps` fills the
    inside of a pipe, valve or housing up to picked openings as a new solid,
    and `ENCLOSURE, b|ALL, margins` puts a box, cylinder or sphere round the
    model with the model cut out (for air around a part). Both list the
    openings and faces they used, as data.
    *Done: FLUIDVOLUME closes each flat end face's hole with a cap (AUTO,
    SEL or face IDs) and keeps the inside that does not reach the outside;
    the answer names the cap faces of the new body. ENCLOSURE takes one
    margin or six; the answer names XMIN ... ZMAX (SIDE/TOP/BOTTOM,
    OUTER) and the model's walls by face ID.*
82. **Parts that share faces** (P2): `IMPRINT` and `SHARE, a, b` split
    touching faces of neighbouring parts so they share the same face where
    they touch, written to STEP so the separate app meshes them as one
    connected piece; `SHARE, ALL, CHECK` lists the touching pairs that are
    still apart. Small
    faces, slivers and short edges that would trouble a mesher are listed by
    `CHECK, b, FLAWS` and can be merged away (`MERGEFACES`).
    *Done, as `SHAREFACES` (SHARE alone reads like sharing the project):
    touching parts are split along their contact so both use the same face
    (one face in BREP; matching faces, edge for edge, in STEP);
    `SHAREFACES, ALL, CHECK` is not kept. `IMPRINT, a, b` splits only a.
    `MERGEFACES, b` joins faces on one surface, `..., SMALL, size` also
    removes slivers.*

### Easier everyday work (M15)

From a second comparison (2026-11-24), this time of how other modellers make
everyday work quicker for people: picking, previews, menus, numbers, help.
Same rule as M14: each item works **by mouse**, **by command** (one
ordinary step or view command, with a form) and **for the assistant** (a
reading tool that returns data, a skill note, benchmark tasks). Not part of
M14 items 68-82 (item 75 already covers mouse styles and custom shortcuts).
Built in this order, about three per pull request.

83. **Live 3D preview in every form** (P0, done: `PREVIEW`, Show in 3D on every form, `preview_step`; a step slower than 1.5 s waits for an Update preview button): while a form is open, the result
    is drawn as a see-through ghost in the 3D view and follows each change of
    a field (fillet sizes, extrude lengths, holes, patterns, shells). A step
    that would fail shows its reason in the form and the faces or edges at
    fault in red, before OK. Built on a copy of the model, cancelled by Esc,
    nothing written to history until OK. Command: `PREVIEW, "step text"`
    (and `PREVIEW, OFF`). Assistant: `preview_step` returns what the step
    would make (bodies, volume change, faces made or removed, problems) as
    data, so it can check a step before running it.

    edge or face nearest the cursor (the toolbar modes stay as filters);
    drag a box (left to right: fully inside, right to left: touching) or a
