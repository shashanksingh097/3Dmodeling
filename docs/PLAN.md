# 3Dmodeling: Product and Technical Plan

This plan turns the idea in the README (every GUI action is a text command,
in our own command language) into a modeler that is usable for real work: precise solids,
freeform NURBS, equation-driven shapes, reusable parts, booleans, freehand
cuts and sculpting, with an AI assistant at the end.

It is organized as:

1. What the best tools do, and what we take from each
2. Key decisions (kernel, viewport, stack)
3. Data model: shapes, objects, IDs, history
4. The command language
5. Feature catalogue
6. Architecture and code layout
7. Milestones with exit criteria
8. Risks and how we handle them

---

## 1. What the best tools do

| Tool | What it does best | What we take |
|------|-------------------|--------------|
| **Command-driven FEA preprocessors** | Everything is a command; selection sets; parameters and loops; the log file is a complete script | The whole command philosophy, selection-set logic, parameters and loops |
| **SolidWorks / Fusion 360 / Onshape** | Sketch, constrain, extrude/revolve/sweep/loft; fillet, chamfer, shell, draft; feature tree you can edit and re-run; parts and assemblies | Sketch + feature workflow, editable history, components/instances |
| **Rhino (+ Grasshopper)** | NURBS curves and surfaces, loft, network surfaces, blend, rebuild, control-point editing, curvature analysis; visual/parametric scripting | NURBS toolbox, analysis (zebra, curvature), "script drives geometry" |
| **FreeCAD** | Open source on OCCT; Python console mirrors GUI actions | Proof that OCCT + Python + Qt works; the "GUI echoes Python" pattern |
| **OpenSCAD / CadQuery / build123d** | Models written as code; parameters at the top; CSG | Code-first modeling, parameter tables, reproducibility |
| **Blender** | Mesh editing (extrude, bevel, loop cut, knife), modifiers stack, sculpt mode, Python API for everything | Knife tool, non-destructive modifier idea, sculpt brushes |
| **ZBrush / Nomad** | Dynamic-topology sculpting, brushes, masking, remeshing | Sculpt mode on meshes (later phase) |
| **nTop / Fusion volumetric** | Implicit (field/SDF) modeling: lattices, smooth blends, equation-defined shapes | Equation-based implicit shapes with smooth booleans |

The gap we fill: none of the free tools combine **precise B-rep CAD, NURBS,
equation geometry and sculpting** under **one replayable command language**
with an AI on top.

## 2. Key decisions

### 2.1 Geometry kernel: Open CASCADE (OCCT)

OCCT is the only mature, free, Python-accessible B-rep kernel. It gives us
exact solids, NURBS curves and surfaces, booleans, fillets, chamfers, shells,
offsets, sweeps, lofts, STEP/IGES import and export, tessellation, and a
history API (which sub-shapes were modified or generated by an operation) that
we need for stable IDs.

- **Binding: OCP** (`cadquery-ocp`, installs with `pip`). It is the binding
  used by CadQuery and build123d and is kept close to current OCCT releases.
- **Helper layer: build123d** for convenient high-level operations (sketches,
  lofts, sweeps, fillets, text). It sits on OCP, so its shapes are plain
  `TopoDS_Shape` objects we can mix with raw OCCT calls. Command handlers may
  use build123d or OCP directly, but the model only stores OCCT shapes.
- **Fallback: pythonocc-core** (conda only). It ships a ready PySide6 viewer.
  If embedding the OCP viewer in Milestone 0 turns out to be fragile, we
  switch the binding; the rest of the plan does not change.

### 2.2 Second representation: meshes

Sculpting, scanned data, STL editing and implicit shapes are mesh problems,
not B-rep problems. The model has two body kinds:

- **Solid / Surface bodies**: OCCT B-rep. Exact. Default for engineering.
- **Mesh bodies**: triangle meshes (`numpy` arrays), edited with
  `trimesh`, booleans with `manifold3d` (robust, fast mesh CSG).

Conversion commands connect them: `MESHIFY` (B-rep to mesh, by tessellation),
`SOLIDIFY` (mesh to B-rep as a faceted solid; true surface fitting is a
later stretch goal).

### 2.3 Viewport: OCCT's own visualization (AIS / V3d) inside PySide6

- OCCT's AIS viewer draws B-rep natively, with exact **sub-shape picking**
  (vertex, edge, face, solid) and highlighting. That is exactly what
  selection commands like `SEL, S, FACE, , 12` need. VTK or a custom OpenGL
  viewer would force us to rebuild face/edge picking ourselves.
- We embed it in a `QWidget` by passing the native window handle to
  `V3d_View` (the approach CQ-editor and FreeCAD-style viewers use).
- Meshes display through `AIS_Triangulation` / `MeshVS`. If high-poly
  sculpting is too slow there, Sculpt mode gets a dedicated `QOpenGLWidget`
  renderer (`moderngl`) in its milestone. That is a contained decision we
  make with measurements, not now.

### 2.4 Stack summary

| Concern | Choice |
|---------|--------|
| Language | Python 3.11+ |
| GUI | PySide6 (Qt 6) |
| Kernel | OCCT via OCP; build123d as helper |
| Viewport | OCCT AIS/V3d embedded in PySide6 |
| Mesh | numpy, trimesh, manifold3d |
| Implicit/equations | numpy expression evaluation, scikit-image marching cubes |
| Expressions | our own safe evaluator over Python's `ast` (no `eval`) |
| Constraint sketcher | our own small solver on numpy (chosen after a spike against planegcs and SolveSpace's solver; see docs/M3-sketcher.md) |
| File formats | native `.cmd` script + `.3dm`-style project zip; STEP, IGES, BREP, STL, OBJ, 3MF, glTF |
| Tests | pytest; headless command tests need no GUI |
| Packaging | pip + `pyproject.toml`; PyInstaller bundles later |
| AI (last phase) | Claude API with tool use; the tools are our commands |

## 3. Data model

### 3.1 Shapes, objects, and reuse

The user's request "create objects, keep them as shapes, use them to create
new objects" maps to three levels:

| Level | What it is | Example |
|-------|-----------|---------|
| **Entity** | Topology inside a body: vertex (`KP`), edge (`LINE`), face (`AREA`), solid (`VOLU`) | face 12 of a block |
| **Body** | One shape in the model with an ID, name, color, layer, material | `VOLU 3` named `bracket` |
| **Part (definition)** | A named, reusable shape recipe: a sub-script with parameters | `PART, bolt, D=8, L=30` |
| **Instance** | A placed copy of a part with its own transform; editing the part updates all instances | `INST, bolt, 10,0,0` |

Bodies are always kept: a boolean like `SUBTRACT` produces a new body and,
by default, hides (not deletes) its inputs, so the inputs stay reusable.
`KEEP, ON|OFF` controls that.

### 3.2 IDs and the "topological naming" problem

Scripts refer to entities by number (`PICK, FACE, 12`). In history-based
CAD, numbers shift when an earlier step changes, and a reference that
silently moves to another face is the worst failure a modeler can have.
Our rules (the first five are built):

1. Bodies and entities get IDs that are stable through operations: after
   every operation, sub-shape IDs are carried forward using OCCT's history
   (`Modified`, `IsDeleted`), with a match by geometry where a builder
   reports nothing. A face that was split keeps its ID on the largest
   piece; faces that were merged keep the first one's ID.
2. Each history entry remembers the IDs it handed out and asks for them
   again on replay, including the ones a shorter run (a smaller loop count)
   did not reach. Project files store them, so open = the model as saved.
3. Every entity knows which history entry made it. A pick stores that with
   a fingerprint (type, place, size, direction). If the ID is gone, or now
   belongs to another entry's work, the pick is repaired from the
   fingerprint only when exactly one entity fits, and the entry is marked
   with a warning. It never guesses between look-alikes; it fails instead.
4. Scripts should prefer **geometric selection** over raw numbers:
   `SEL, S, FACE, NORMAL, 0,0,1`, `SEL, S, FACE, LOC, Z, 2`,
   `SEL, S, EDGE, OF, FACE`. Raw IDs remain available.
5. Named selections (`CM, top_faces, FACE`) give stable handles a script can
   reuse.

Still to do:

6. Name faces made by an operation by their parents ("the wall between
   face 6 of the plate and the side of hole 3"), so new faces of a boolean
   are found again even when the kernel returns them in another order. `[M3]`
7. Fingerprints for `SEL ..., ID` lists and named sets, and an option for
   the GUI to write a click as a geometric criterion when one identifies
   the entity uniquely (so plain scripts carry no raw IDs). `[M3]`

### 3.3 History = the command log

There is no separate feature tree file format. The command log *is* the
history. The **History panel** shows it as a tree (grouped by part and by
GUI action), and editing an old command re-runs the script from that point.
Undo/redo walks the log; snapshots every N commands make re-runs fast.

## 4. The command language

Comma separated, case-insensitive, one command per line.

```text
! comment
NAME, arg1, arg2, , arg4      ! empty args take defaults
```

### 4.1 Parameters and expressions

```text
W = 40                      ! scalar parameter
H = W/2
R = sqrt(W**2 + H**2)/4
P = (10, 0, 5)              ! point/vector
BLOCK, 0,0,0, W,H,5
```

Expressions support `+ - * / ** %`, `sin cos tan asin acos atan atan2 sqrt exp
log abs min max floor ceil`, `pi`, `e`, and model queries such as
`VOL(3)`, `AREA(12)`, `CENT(3).x`, `BBOX(3).zmax`, `NSEL(FACE)`.

### 4.2 Control flow and macros

```text
*DO, i, 1, 8
  CYL, 30*cos(i*pi/4), 30*sin(i*pi/4), 0, 3, 10
*ENDDO

*IF, W, GT, 30, THEN
  FILLET, EDGE, sel, 2
*ENDIF

*MACRO, drill, x, y, d          ! user macro = new command
  CYL, x, y, -1, d/2, 100
  SUBTRACT, VOLU, base, last
*END
drill, 10, 10, 6
```

`*PY ... *ENDPY` runs a Python block with the model API, for anything the
language can't express. It is off by default for scripts from others.

### 4.3 Command families (initial list)

| Family | Commands |
|--------|----------|
| Points/curves | `K` (keypoint), `LINE`, `ARC`, `POLYLINE`, `SPLINE` (interpolate), `NURBSCRV` (control points, weights, knots), `HELIX`, `CURVE, PARAM, x(t), y(t), z(t), t0, t1`, `JOIN` |
| Profiles | `CIRCLE`, `ELLIPSE`, `RECT`, `POLYGON`, `SLOT`, `STAR`, `AIRFOIL` (NACA 4-digit), each on any plane |
| Sketch | `SKETCH, plane` ... `ENDSKETCH`, `RECT`, `POLYGON`, `SLOT`, `TEXT`, constraints `CON, COINCIDENT/PARALLEL/TANGENT/DIST/ANGLE/RADIUS ...`, `TRIM`, `OFFSET2D` |
| Primitives | `BLOCK`, `CYL`, `CONE`, `SPHERE`, `TORUS`, `WEDGE`, `PRISM`, `PYRAMID`, `TUBE`, `CAPSULE` |
| Sketch-based features | `EXTRUDE`, `REVOLVE`, `HOLE`, `RIB`, `THREAD` |
| Shapes on curves | `LOFT`, `SWEEP` (with twist/scale/offset laws, several profiles to morph, rails), `PIPE`, `SWEEPVOL`, `FLOW`, `BEND`, `TWIST`, `TAPER` (see 5.2) |
| Surfaces | `NURBSSRF` (control net), `SURF, PARAM, x(u,v), y(u,v), z(u,v)`, `LOFTSRF`, `NETWORK` (curve network), `PATCH` (fill boundary), `BLENDSRF`, `PIPE`, `OFFSETSRF`, `EXTENDSRF`, `SEW` (surfaces to solid), `REBUILD` |
| Implicit / equations | `IMPLICIT, f(x,y,z), bbox, res` (shape is where f ≤ 0), `GYROID`, `LATTICE`, smooth booleans `SUNION`/`SSUBTRACT` with blend radius |
| Booleans | `UNION` (`VADD`), `SUBTRACT` (`VSBV`), `INTERSECT` (`VINV`), `SPLIT` (body by plane/surface/body), `IMPRINT`, `GLUE` |
| Modify | `FILLET`, `CHAMFER`, `SHELL`, `DRAFT`, `OFFSET`, `THICKEN`, `DEFEATURE`, `PUSHPULL` (face), `MOVEFACE`, `DELFACE`, `REPLACEFACE` |
| Transform/pattern | `MOVE`, `ROTATE`, `SCALE`, `MIRROR`, `ALIGN`, `COPY`, `ARRAY, LINEAR/POLAR/PATH` |
| Freehand | `STROKE` (recorded mouse points), `KNIFE` (cut by stroke projected through view), `SLICE` (by plane), `SCULPT, brush, ...` |
| Mesh | `MESHIFY`, `SOLIDIFY`, `REMESH`, `DECIMATE`, `SMOOTH`, `MESHBOOL` |
| Parts/reuse | `PART ... ENDPART`, `INST`, `EXPLODE`, `LIB, SAVE/LOAD` |
| Selection | `SEL, S/R/A/U/ALL/NONE/INVE, type, criterion, ...`, `CM` (named set), `CMSEL`, `PICK` (the raw GUI pick) |
| Display/view | `VIEW, ISO/TOP/FRONT/...`, `ZOOM`, `FIT`, `SHOW`, `HIDE`, `COLOR`, `LAYER`, `SECTION`, `ANALYZE, ZEBRA/CURVATURE/DRAFT` |
| Measure | `DIST`, `ANGLE`, `MASSPROP`, `CHECK` (validity) |
| Files | `SAVE`, `OPEN`, `IMPORT`, `EXPORT, STEP/IGES/STL/OBJ/3MF/GLTF`, `RUN, file.cmd`, `LOG, ON/OFF` |
| Session | `UNDO`, `REDO`, `CLEAR`, `/UNITS`, `/TOL` |

Every GUI tool is a thin form that fills in one of these commands. The
command it built is shown in the form before it runs, and lands in the
History panel and the log, so users learn the language by using the GUI
(docs/M2-forms.md).

### 4.4 Selection in detail

```text
SEL, S, VOLU, ID, 3              ! select body 3
SEL, R, FACE, NORMAL, 0,0,1      ! reselect: keep faces facing +Z
SEL, A, EDGE, LENGTH, GT, 10     ! add edges longer than 10
SEL, S, FACE, BOX, 0,0,0, 10,10,2
SEL, S, EDGE, OF, FACE, sel      ! edges of the selected faces
CM, top, FACE                    ! save as named set
FILLET, EDGE, sel, 1.5           ! "sel" = current selection
```

A viewport click emits `PICK, FACE, 12` which the processor translates into
the most robust equivalent (`SEL, S, FACE, ...`) when it writes the log.

## 5. Feature catalogue

Grouped by what the user asked for. `[M#]` is the milestone that delivers it.

### 5.1 Basic and complex shapes
- Primitives with full parameters and placement `[M1]`
- 2D sketches with constraints, then extrude/revolve `[M3]`
- Sweeps, lofts, pipes and helices, with shapes that change along the path: see 5.2 `[M2]`/`[M4]`/`[M5]`
- Text and logos (font outlines to sketches) `[M4]`

### 5.2 Shapes on curves: sweeps, lofts and morphing

The idea: take a section (a profile), move it along a curve, and let it
change on the way: turn, grow, shrink, stretch, or turn into a different
shape. Every one of these is a command, so a blade, a horn, a handrail or a
spring is a short script whose numbers you can change later.

**Curves to sweep along (paths)** `[M2]`
- `LINE`, `ARC` (3 points or center/angle), `POLYLINE`, `SPLINE` through points (with optional end tangents)
- `HELIX`: radius, pitch, turns, left/right hand, taper angle, and a pitch law for springs with closer coils at the ends
- `CURVE, PARAM, x(t), y(t), z(t), t0, t1`: any equation, fitted to an exact B-spline
- `JOIN` curves into one path; `EDGE` of a body as a path (sweep along a model edge)

**Profiles (the moving shape)** `[M2]`
- `CIRCLE`, `ELLIPSE`, `RECT` (with corner radius), `POLYGON` (n sides), `SLOT`, `STAR`, `AIRFOIL` (NACA 4-digit: chord, camber, thickness)
- Each one is placed on any plane (origin, normal, and an X direction), and a closed `POLYLINE`/`SPLINE` is a profile too
- Later: any sketch from the sketcher `[M3]`, text outlines `[M4]`

**Loft: a smooth shape through sections** `[M2]`
- `LOFT` through 2 or more sections: smooth (one B-spline surface) or ruled (straight between sections)
- Closed lofts that loop back to the first section (a ring with a changing section)
- Sections with different shapes and point counts (circle to square to star); start points matched so the surface does not twist by accident
- Solid or open surface; caps on or off
- Loft along a spine curve, so the sections follow a curved center line `[M4]`
- Loft with guide curves that the side of the shape must pass through `[M5]`

**Sweep: drag a profile along a path** `[M2]`
- `SWEEP, profile, path`: exact sweep of one profile
- Orientation modes: follow the curve (Frenet), minimal twist (the default; no flips on 3D curves), fixed direction, keep a chosen "up" direction (binormal), and follow a surface's normal `[M5]`
- Sharp or rounded corners on polyline paths
- Solid or open (a surface), and keep the profile perpendicular to the path or as placed

**Laws: how the profile changes along the path** `[M2]`
- A law is an expression in `t`, where `t` goes from 0 at the start of the path to 1 at the end, so it can use parameters and any math:
  - twist: `"40 - 32*t"` degrees
  - scale: `"1 - 0.5*t**2"`, or separate X and Y scales to stretch the section
  - offset: slide the profile off the path (a cam track, an S-shaped duct)
- Laws can also be a table of stations (`t, value` pairs), interpolated smoothly; this is what the GUI edits `[M3]`
- Laws work in `SWEEP`, `PIPE`, `HELIX` (pitch) and `ARRAY, PATH` (spacing, scale, turn)

**Morph: the profile turns into other shapes on the way** `[M2]`
- `SWEEP` with several profiles placed at stations along the path: a round duct that turns square, then flat; a blade root that turns into an airfoil
- Laws (twist, scale) apply on top of the morph

**Rails: curves that steer the shape** `[M4]`
- One guide rail: the profile turns so a chosen point always touches the rail (a twisted handrail, a ribbon)
- Two rails: the profile is turned and scaled so it spans both rails (a wing between its leading and trailing edges, a ship hull, a guitar neck)
- Rails and laws combine: rails set the size, a law adds thickness change

**Pipes, springs and threads**
- `PIPE, path, r`: round tube along any curve, solid or hollow (wall), with a radius law `[M2]`
- Springs: `HELIX` + `PIPE`, variable pitch, ground ends `[M4]`
- Threads: a thread profile swept on a helix, added or cut, standard metric sizes `[M4]`

**Shape follows a curve (deformers)** `[M5]`
- `FLOW`: bend an existing body so it follows a curve (a straight text or pattern wrapped onto a path)
- `BEND`, `TWIST`, `TAPER`, `STRETCH` of whole bodies, with laws; exact on B-rep where OCCT allows, through NURBS approximation otherwise; meshes always
- `SWEEPVOL`: the volume a moving tool body sweeps through (a cutter path, a keyway), so it can be cut away with `SUBTRACT`

**Patterns along a path** `[M2]`
- `ARRAY, PATH`: copies along a curve, keeping their orientation to the curve, with count or spacing, and laws for scale and turn (chain links, a spiral staircase, beads)

**Working with it in the GUI** `[M3]`
- Pick the profile and path in the viewport, and a preview appears
- A slider moves a "ghost" section along the path, showing what it looks like at that `t`
- Handles at stations set twist and scale by dragging; each drag edits the law table through `HIST, EDIT`, so the command stays the source of truth
- A small graph shows each law over `t`

### 5.3 NURBS and freeform
- NURBS curves: control points, degree, weights, knot editing; interpolate through points `[M5]`
- NURBS surfaces: from control net, loft, network of curves, patch/fill, blend between surfaces with G1/G2 continuity, extend, offset, trim by curves `[M5]`
- Control-point editing in the viewport (drag points, each drag is a `MOVEPT` command) `[M5]`
- Rebuild/reparameterize, sew surfaces into solids `[M5]`
- Analysis: zebra stripes, Gaussian/mean curvature map, draft angle `[M5]`

### 5.4 Equation-based geometry
- Parametric curves `x(t), y(t), z(t)` and surfaces `x(u,v), y(u,v), z(u,v)`, fitted to NURBS so they become exact geometry usable in booleans `[M4]`
- Implicit shapes `f(x,y,z) ≤ 0` (gyroids, metaballs, superquadrics), meshed by marching cubes; smooth blends between them `[M6]`
- Lattice infill of a solid (gyroid, cubic, octet) `[M6]`
- Driven dimensions: any number in any command can be an expression of parameters `[M2]`

### 5.5 Reuse and operations
- Bodies kept and reusable after booleans (`KEEP`) `[M2]`
- Parts with parameters, instances that follow the definition, part library across projects `[M4]`
- Booleans, split, imprint `[M2]`; fillet, chamfer, shell, draft, offset, thicken `[M3]`
- `SPLIT` by a plane or a body, `HOLE` (simple, counterbore, countersink, drill point; one command instead of cylinder plus subtract), `SHELL`, `DRAFT`, `OFFSET` `[done]`; threaded holes `[M4]`; variable-radius and face fillets `[M3]`
- Faster repeated cuts: `SUBTRACT, a, SEL` takes many tools in one kernel call `[done]`; `ARRAY ... CUT`; patterns of features (repeat the last steps, not just a body) `[M3]`
- Direct editing: push/pull a face, move/delete faces (great on imported STEP) `[M4]`
- Patterns: linear, polar, along a path `[M2]`

### 5.6 Freehand
- **Knife**: draw a stroke on screen, it is projected through the view and cuts or splits the body (`KNIFE`) `[M6]`
- **Freehand sketch**: draw a closed stroke on a face or plane, it is fitted to a spline, then extruded as cut or boss `[M6]`
- **Sculpt mode** on mesh bodies: draw, clay, inflate, smooth, flatten, crease, grab, mask; symmetry; remesh/dynamic resolution `[M7]`
- Every brush stroke is logged as `SCULPT, brush, radius, strength, stroke-file-ref`, so sculpting is replayable too (stroke points saved in the project zip)

### 5.7 Productivity and real-life use
- Units (mm, cm, m, in) and tolerances `[M1]`
- Snap (grid, endpoints, midpoints, centers), work planes, measure tools `[M3]`
- **Datum geometry**: planes, axes and points as named objects (`PLANE`, `AXIS`, `POINT`), from numbers or from faces and edges, and `WORKPLANE` so primitives, profiles and holes are drawn on any plane `[done]`. Next: let the sketcher sit on them `[M3]`
- **Measure commands**: `DIST`, `ANGLE`, `MASSPROP` (volume, mass, centre, inertia with a material density), `CLASH` (overlap and clearance between bodies) `[done]`; minimum wall thickness `[M3]`
- Layers, colors, materials, mass properties `[M3]`
- Section view (`SECTION`) and hide/show `[done]`; isolate `[M3]`
- Import/export STEP, IGES, STL, OBJ, 3MF, glTF; drawings (2D projection to DXF/SVG) later `[M2]`/`[M8]`
- Autosave and crash recovery from the log `[M2]`
- Results checked after every boolean and blend, `CHECK`, `HEAL`, `CLEAN` `[done]`; auto-heal on import, sewing with a tolerance, defeaturing (remove small holes and fillets) `[M4]`
- History that stays fast: skip entries whose inputs did not change (dependency tracking), rebuild on a worker thread with progress and cancel, so the window never freezes `[M3]`
- Undo for history edits themselves (`HIST, EDIT/DELETE/MOVE` are not yet undoable) `[M3]`
- Warning state for history entries (ran, but needs a look) `[done]`
- Separate namespaces, or a clear error, when a parameter and a body share a name `[M3]`
- Assemblies: instances placed by mates (coincident, concentric, distance, angle) or at least by placement constraints, with interference check `[M4]`
- Regression corpus: example scripts whose volumes, face counts and validity are checked in CI, so a kernel upgrade cannot change models unnoticed `[M3]`
- Configurations: named sets of parameter values for one model (sizes of a family of parts), switchable from the Parameters panel and from the batch runner `[M4]`

### 5.8 AI assistant (last)
- Chat panel that explains any command, turns plain language into a command script, explains errors, and can read the current model state through query commands `[M9]`
- The AI never edits the model directly; it proposes commands, the user sees and accepts them, and they run through the same processor and log.

## 6. Architecture

```
 ┌───────────── gui/ (PySide6) ─────────────┐
 │ toolbars & forms → build command text    │
 │ command line, log, history tree, params  │
 │ viewport/ (OCCT AIS)  → PICK commands    │
 └──────────────┬───────────────────────────┘
                │ text
        ┌───────▼────────┐
        │ commands/      │ lexer → parser → expression eval → registry
        │ processor      │ → handler(args, model) → result
        └───────┬────────┘
                │ API calls only
        ┌───────▼────────┐        ┌────────────┐
        │ core/ model    │◄──────►│ geometry/  │ OCCT wrappers, mesh ops,
        │ bodies, IDs,   │        │            │ implicit, NURBS fitting
        │ selection, undo│        └────────────┘
        └───────┬────────┘
                │ change events (body added/changed/removed)
                ▼
        viewport refresh
```

Rules:

- The model knows nothing about Qt. The whole core runs headless, so every
  command is unit-tested without a window, and scripts can run in batch mode
  (`python -m modeler run bracket.cmd --export bracket.step`).
- Handlers register themselves with a decorator that declares argument names,
  types, defaults and help text. The same metadata drives the parser, the
  GUI forms, `HELP, CMD`, autocomplete, and the AI's tool list.
- Long operations (big booleans, meshing) run on a worker thread with a
  progress bar and cancel.

Code layout:

```
modeler/
  commands/      parser.py, expr.py, registry.py, processor.py, handlers/*.py
  core/          model.py, body.py, ids.py, selection.py, history.py, units.py
  geometry/      occ_ops.py, nurbs.py, param_fit.py, implicit.py, mesh_ops.py, io.py
  gui/           main_window.py, command_line.py, log_panel.py, history_tree.py, forms/
  viewport/      occ_view.py, picking.py, overlays.py, sculpt_view.py
  ai/            (M9)
scripts/         examples (*.cmd)
tests/
```

## 8. Risks

Ranked by how much each one decides whether the app can be trusted for real
work. Numbers were measured in November 2026 on the code after M2.

| # | Risk | State | What is built | What is left |
|---|------|-------|---------------|--------------|
| 1 | **References break when history is edited** (the topological naming problem). A pick that silently moves to another face makes every edited model suspect. | Much reduced | IDs carried through operations; IDs kept per entry, also when a loop shrinks and grows; IDs saved in project files; picks know which step made the entity and are repaired by fingerprint only when the match is unique, with a warning | Parent-based names for faces made by booleans; fingerprints for ID lists and named sets; GUI picks written as criteria (3.2, items 6 and 7) |
| 2 | **The kernel returns bad shapes without saying so.** Measured: an oversized fillet gave an invalid body, a subtract that removed everything gave an empty body, a union left seams. | Much reduced | Every boolean and blend is checked; empty and invalid results are errors with the model unchanged; oversized fillets name the size that works; retry with a tolerance; seams merged; `CHECK`, `HEAL`, `CLEAN`; `HOLE`, `SPLIT`, `SHELL`, `DRAFT` and `OFFSET` are checked the same way (a shell too thick names the thickest wall that works) | Same checks for `LOFT`/`SWEEP`/`PIPE`; a corpus of hard cases in CI |
| 3 | **Rebuilding long histories is slow.** Measured: 300 holes cut one by one take 13 to 15 s to build, and the same again after an edit near the start; an edit to the last entry takes 0.1 s; undo is instant. The time is inside the kernel, which rebuilds the whole body for each cut. | Partly reduced | Snapshot after every entry, so only entries from the edit onwards re-run; `SUBTRACT, a, SEL` cuts all selected bodies in one kernel call (the 300 holes: 0.4 s instead of 13 s) | `ARRAY ... CUT` and feature patterns that use the same one-call route; skip entries whose inputs did not change; rebuild on a worker thread with progress and cancel |
| 4 | **Sketcher and constraint solver.** The largest piece of new work, and the part users touch most. | Much reduced | Spike against planegcs and SolveSpace's solver (docs/M3-sketcher.md); own numpy solver, split into independent groups, with degrees of freedom, redundant and conflicting constraints named; a refused constraint leaves the sketch as it was; sketch steps are history entries, so a size edit re-runs the model | Real-user testing of the mouse tools; trim, offset and fillet in sketches; planegcs as a faster back end if big sketches get slow |
| 5 | **The viewer on real desktops** (macOS, HiDPI, Wayland). | Linux under a virtual display and Windows CI work; macOS and real GPUs untested | M0 spike, per-OS checklist in docs/M0.md | A run on a real Windows or macOS machine; pythonocc-core's viewer is the fallback |
| 6 | **Mesh and CAD interop** (STL bodies in booleans, solid to mesh and back). | Not started | STL import sews to a solid when closed | Mesh bodies with `manifold3d` booleans (M6) |
| 7 | Sculpting performance in Python | Not started | | numpy/numba brush kernels; a dedicated renderer if needed (measured in M7) |
| 8 | Scope is huge | Managed | Each milestone is usable alone | Features after M2 are ordered by the user |
