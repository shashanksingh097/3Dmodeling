# M1: the command core

M1 turns the M0 spike's one-line parser into a real language with a history
you can edit. The language reference is [LANGUAGE.md](LANGUAGE.md).

## What is in it

| Piece | File | What it does |
|-------|------|--------------|
| Expressions | `modeler/lang/expr.py` | Safe evaluator over Python's `ast` (no `eval`): numbers, points, text, math, model queries |
| Script reader | `modeler/lang/script.py` | Comments, argument splitting, blocks (`*DO *IF *WHILE *MACRO`), top-level units |
| Processor | `modeler/commands/processor.py` | Registry, argument binding, the interpreter, history, undo/redo, history editing |
| Queries | `modeler/commands/queries.py` | `VOL AREA LENGTH CENT BBOX NSEL SELID COUNT BODY OWNER EXISTS PARAM` |
| Commands | `modeler/commands/handlers.py` | Primitives, booleans, blends, transforms, names, selection by criteria, named sets, units, export, history |
| Model | `modeler/core/model.py` | Snapshots, ID carry-over through operations, pinned IDs on replay, names, named sets |
| GUI | `modeler/gui/main_window.py` | History panel, Parameters panel, Undo/Redo, block input in the command line |

The rule from the plan still holds: the GUI never edits the model. Editing a
parameter in the Parameters panel sends `HIST, EDIT, 6, "N_BOLTS = 8"`;
double-clicking a history entry opens an editor whose OK sends the same
command. You see each of those in the output panel.

## Try it

```bash
pip install -e ".[test]"
python -m modeler scripts/flange.cmd
```

Then:

1. In **Parameters**, change `N_BOLTS` from 6 to 8. The flange rebuilds, and
   the fillet and chamfer still land on the right edges.
2. Right-click entry 18 (the first `SEL` after the bolt loop) in **History**, "Insert before…", and
   add a block, for example:

   ```text
   *DO, j, 0, N_BOLTS - 1
     A2 = (j + 0.5) * 360 / N_BOLTS
     drill, PCD/2 * cos(A2), PCD/2 * sin(A2), 3
   *ENDDO
   ```

   The later steps still find their faces and edges.
3. Ctrl+Z / Ctrl+Y walk the history; undone entries turn grey.
4. Type a block in the command line: the prompt changes to `…` until `*ENDDO`.
5. Headless: `python -m modeler run scripts/flange.cmd -D N_BOLTS=12 -q`.

## How the stable IDs work

* **Carry-over.** When a body is made from other bodies, the OCCT builder's
  history (`Modified`, `IsDeleted`) maps old faces, edges and vertices to new
  ones. Unchanged sub-shapes are found directly. A split entity keeps its ID
  on the largest piece. Fillet and chamfer makers rebuild untouched faces
  without reporting them, so those are matched by geometry (same centre and
  size). One surprise found on the way: the fillet maker reports *every*
  input edge as deleted, so the direct lookup runs before `IsDeleted`.
* **Pinning.** Each history entry records, per kind, the IDs it handed out.
  On a replay it asks for them again in the same order, and new entries draw
  fresh IDs above every pinned one. That is what keeps `PICK, FACE, 12`
  pointing at the same face after an earlier step is inserted or changed.
* **Snapshots.** Bodies are immutable, so a snapshot after every entry is a
  few dictionary copies. Undo/redo restore a snapshot; an edit restores the
  one before the edited entry and re-runs only from there.

## Not in M1 (later milestones)

* `KEEP, ON` to keep boolean inputs, patterns (`ARRAY`), import, save/open of
  a project file, autosave: M2 as planned.
* Command-line autocomplete and a form for each command: M2.
* `*PY` blocks: left out on purpose until there is a trust setting for
  scripts from others.
* `HIST` edits are not themselves undoable yet; `UNDO` steps through entries.
* Picks are recorded by ID. IDs now survive operations and history edits, but
  a pick on a face that a later parameter change removes will fail (and is
  marked red); geometric `SEL` criteria are the robust choice in scripts.
